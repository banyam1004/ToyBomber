## 프로젝트 소개
C++ IOCP 기반 실시간 멀티플레이 봄버맨 서버 + Unity 클라이언트

## 개발 배경 및 목적
이전 IocpServer(채팅 서버) 프로젝트에서 세워둔 개선 방향 중 "Unity 클라이언트 연동으로 실제 게임 구현"을 실행에 옮긴 프로젝트. 단순 텍스트 브로드캐스트가 아니라 위치 동기화, 충돌, 타이머 기반 이벤트(폭탄 폭발)처럼 실시간성이 요구되는 게임 로직을 서버가 직접 처리하도록 설계하고, 이를 검증할 수 있는 클라이언트까지 함께 구현

## 기술 스택
서버: C++ / Winsock2 / IOCP / std::thread / std::mutex
클라이언트: Unity / C#

## 주요 기능
* 방 생성 / 입장, 유저ID·방ID 할당
* 맵 정보 전송 및 렌더링(타일 기반)
* 4인 동시 접속, 코너별 스폰 위치 배정(스폰 지점 3x3 개활 처리로 시작 직후 고립 방지)
* 실시간 이동 동기화
* 폭탄 설치 / 타이머 기반 폭발 판정 / 파괴 가능 타일 처리
* 플레이어 사망 판정 및 생존자 1인 이하 시 게임 종료
* Unity 클라이언트: 타일 충돌(벽에 딱 맞춰 정지), 카메라 추적, 창 비활성 상태에서도 네트워크 로직 유지

## 서버 구조

### 전체 흐름
1. 서버 시작 -> IOCP 완료 포트 생성 -> 워커 스레드 대기
2. 클라이언트 접속 -> IOCP에 소켓 등록 -> 전역 클라이언트 목록에 추가
3. 방 생성/입장 요청 -> 방 배정 -> 유저ID·방ID 전송
4. 게임 시작 -> 맵 정보 전송 -> 플레이어별 스폰 좌표 계산 및 브로드캐스트
5. 이동/폭탄 설치 요청 수신 -> 상태 갱신 -> 같은 방 클라이언트에 브로드캐스트
6. 폭탄 타이머 만료 -> 폭발 범위 계산 -> 파괴 가능 타일 제거, 범위 내 플레이어 사망 처리 -> 브로드캐스트 -> 생존자 1인 이하면 게임 종료

### 스레드 구조
* 메인 스레드: accept()로 클라이언트 접속 대기, 접속 시 IOCP에 소켓 등록
* 워커 스레드: GetQueuedCompletionStatus()로 완료 포트 대기, 데이터 도착 시 패킷 처리 후 재대기
* 폭탄 타이머 스레드: 폭탄 설치 시점마다 생성되는 detached 스레드, 지연 후 폭발 처리 함수 호출

### 동시성 처리
* 방 목록 / 전역 클라이언트 목록 각각 별도 mutex로 접근 제어
* 이미 락을 잡은 함수 내부에서 같은 락이 필요한 로직을 호출해야 하는 경우, "락을 이미 잡은 상태에서 쓰는 내부용 버전"과 "직접 락을 거는 공개용 버전"으로 함수를 분리해 재진입 데드락 방지

### 패킷 구조
[헤더][바디] 형태의 고정 헤더 + 가변 바디 구조. 헤더에 패킷 타입과 크기를 포함해 TCP 스트림에서 메시지 경계를 구분

## 좌표계
서버가 authoritative하게 위치를 관리하며, 논리적인 타일 좌표는 정수 기반 그리드. 클라이언트 렌더링 시 스프라이트 기준점(피벗)을 타일 좌표계와 일치시켜야 시각적 위치와 실제 판정 위치가 어긋나지 않음

## 트러블슈팅
* 방 관리 재진입 데드락
  방 나가기 처리 중 이미 락을 잡은 함수 안에서 같은 락이 필요한 내부 로직을 다시 호출하며 스스로 대기 상태에 빠짐
  해결: 락을 이미 잡은 상태에서 쓰는 내부용 함수와, 직접 락을 거는 공개용 함수로 분리
* 이동 동기화 누락
  이동 패킷의 응답 데이터는 만들었지만 실제 브로드캐스트 호출이 빠져 있어, 한 클라이언트가 움직여도 다른 클라이언트 화면에는 반영되지 않음
  해결: 브로드캐스트 호출 추가
* 초기화 범위 오류로 기본값 소실
  클라이언트 접속 정보 구조체 전체를 매 수신마다 초기화하면서, 최대 폭탄 개수 같은 기본 설정값까지 함께 지워짐
  해결: 실제로 초기화가 필요한 통신용 멤버만 범위를 좁혀 초기화
* 전역 클라이언트 목록 등록 누락
  접속 시 전역 클라이언트 목록에 등록하는 코드가 빠져 있어, 폭탄 소유자를 소켓으로 조회하는 로직이 항상 실패
  해결: 접속 시 목록에 추가하는 코드 추가, 대칭으로 접속 종료 시 목록에서 제거하는 코드도 함께 추가(댕글링 포인터 방지)
* 타일 좌표-렌더링 기준점 불일치
  타일 스프라이트의 기준점이 칸의 중앙으로 설정되어 있어, 내부적으로 칸의 왼쪽 아래 모서리를 의미하는 좌표와 반 칸씩 어긋남. 벽을 뚫고 지나가거나 폭발 범위가 엉뚱한 칸에서 표시되는 현상으로 나타남
  해결: 타일 스프라이트 기준점을 칸의 왼쪽 아래로 변경, 플레이어·폭탄처럼 점으로 취급되는 오브젝트는 스폰 좌표에 반 칸 오프셋을 더해 시각적으로 칸 중앙에 위치하도록 보정
* 벽 충돌 시 정지 간격 불균일
  이동 벡터 전체를 한 번에 검사해 막힌 경우 이동 자체를 취소하는 방식이라, 타이밍에 따라 벽과의 간격이 들쭉날쭉하게 남음
  해결: X축과 Y축을 각각 따로 검사해, 캐릭터 폭의 절반만큼 벽 경계에 딱 맞춰 정지하도록 변경

## 한계점
* 로그인/인증 없이 익명으로 접속
* 방 인원 4인 고정, 별도 매치메이킹 없음
* 접속 종료 후 재접속 처리 없음
* 단일 프로세스 구조로 다수 방 동시 처리 시 확장성 고려 안 됨
* 패킷 암호화 없이 평문 전송
* 자동화된 테스트 없이 다중 클라이언트 수동 실행으로 검증

## 개선방향
* 이전 프로젝트(IocpServer)에서 사용한 DB 연동 방식을 가져와 로그인/유저 데이터 저장 추가
* 패킷 암호화 적용(XOR 우선 적용 후 TLS/SSL 검토)
* 접속 종료 시 재접속 처리 및 예외 상황 복구 로직 추가
* 여러 방을 동시에 원활히 처리할 수 있도록 서버 구조 확장
* 이동처럼 유실되어도 큰 문제가 없는 데이터는 UDP 병행 처리로 지연 개선
